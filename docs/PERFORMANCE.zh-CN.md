# 性能与资源设计

## 负载来源

管理页面的绘制和交互发生在浏览器中。路由器提供静态资源、RPC 状态与配置操作。主要持续负载来自音频转码、并发流、设备发现和日志；不能把好看的 UI 等同于高路由器负载，也不能无测量保证零影响。

现有 LuCI 视图使用 poll 定期查询 service.list，因此页面数量、轮询周期和返回大小均需控制。AirConnect 上游说明 FLAC 使用更多 CPU，发现扫描约每 30 秒进行；是否调整必须结合源码支持和实际数据。

来源：https://github.com/philippe44/AirConnect/blob/1.12.4/README.md （Config file parameters / Common information）

## 实现约束

- 前端预构建为静态资源，不在路由器运行 Node/Vite 开发服务器。
- 首版以 LuCI 原生 JS 加局部样式实现 shadcn 风格；不依赖外部 CDN、在线字体或遥测。
- 前台状态默认 5–10 秒更新，隐藏时暂停；错误时退避，每类请求最多一个在途任务。此频率是设计目标，待实现验收。
- 后端短时缓存发现结果，各页面共享；手动扫描防抖、串行、限时，不因每次读状态而启动完整扫描。
- 日志按需加载，限制条数、字节和文件大小，不轮询完整文件或无限增加 DOM。
- 将静态设备信息与动态状态分开，状态刷新不重绘整个表单，也不覆盖未保存输入。
- 不默认执行转码基准或增加并发流，不在用户正在播放时自动重启服务。

## 测量与验收

覆盖：关闭管理页面、单页面、多个标签、隐藏标签、一条和多条播放流、扫描、日志打开、应用配置。分别记录请求频率/响应大小、页面首屏资源量、浏览器长任务、路由器 CPU、RSS、网络与播放中断情况。

RSS 才是进程实际驻留内存指标，VSZ 是虚拟地址空间，不可混用。空闲快照不能代替播放/转码峰值测试。

这七个项目直接对应“实现约束”里“前台状态默认 5–10 秒更新，隐藏时暂停；错误时退避，每类请求
最多一个在途任务。此频率是设计目标，待实现验收”那一条。该条现在是**已验收**（限主机侧
逻辑与载荷）：数字与断言都在上面两个套件里，任何一条被改坏都会让 `run-tests.sh` 变红。

**仍然只能上设备测**，本文件不为它们给出任何数字：路由器 CPU（空闲、单流、多流、FLAC
转码、扫描中）、`airupnp`/`aircast` 的 RSS 与 VSZ、路由器内存峰值、网络流量与突发、
播放中断、浏览器长任务与首屏渲染时间、多标签页在真实浏览器中的实际频率、真实 rpcd/
ubus 的 blob 与 HTTP 外层开销。逐项理由见结果文件的“未测量”一节。

因此 [ROADMAP](../ROADMAP.zh-CN.md) 里“把性能作为实现验收”一项保持 `[ ]`：
载荷、轮询契约与资源清单已测，**以重构前后同条件对比证明不会明显影响播放**这一条不能
在没有播放的情况下成立。

当前现场快照：路由器约 3.83 GiB 总内存、2.87 GiB 可用；airupnp VmRSS 2140 KiB、VmSize 924608 KiB，top 单次样本为 0% CPU。仅用于说明采样时状态，不作为重构后的性能承诺，也未确认采样时存在播放。

目标：页面关闭/隐藏不新增周期性管理请求；不引入额外常驻进程；UI 状态请求不触发媒体处理；以重构前后同条件对比证明不会明显影响播放。首版先测再定数值预算，不能用未经测量的 CPU/内存目标当作结果。

对最后一条的现状：三个套件的预算**都是先测再定**的，不只写在代码里；`measure-status.uc`
初稿把 64 台设备的上限按经验定在 32 KiB，被实测的 35,167 B 当场推翻，上限据此改为
64 KiB——这正好是“不能用未经测量的目标当作结果”的一个实例。

# AirConnect management UI

The approved direction is a quiet system settings page with shadcn-inspired neutral surfaces, 6–9px control/card radii, thin borders and text-first service states. It uses native LuCI forms, navigation, permissions and save/apply. No React, runtime Node, online fonts or CDN are shipped.

The default Speakers tab puts the original name next to the AirPlay name override. UPnP shows its volume limit; Chromecast shows media volume with a distinct explanation. Empty overrides inherit global settings. Audio format, buffering and the advanced compatibility parameters live inside native details disclosures. Device facts never substitute an inferred model, manufacturer, address or timestamp. Discovered and service-running labels do not claim successful playback; broadcast and playback are explicitly unknown until measured.

The advanced parameters are compatibility tuning, not improvements: track metadata and an optional cover-art URL (both engines), FLUSH handling and timing drift (both engines), the HTTP transfer mode and UPnP search version (UPnP only), and stopping the Cast receiver (Chromecast only). Each keeps its upstream default, and the panel says so instead of marketing a change as better. Engine-specific fields are labelled with their engine, because a global value is written to the engine that reads it and silently ignored by the other. Per-device controls are offered only for the device's own engine and accept an empty value, which means "inherit"; `upnp_max` is global only because upstream parses a device-level value but never reads it.

## The four states

Service running, discovered, broadcasting and playing are four separate rows decided by four separate sources, and no one of them may be derived from another. Running comes from procd, discovered from the SSDP cache, broadcasting from an mDNS observation of the `_raop._tcp` service the engines register, and playing is a constant unknown because the engines expose no documented status interface.

Broadcasting is the only one of the four that is newly measurable, and it is measured narrowly: the observation records which engines have a `_raop._tcp` instance advertised and which MAC prefixes those instances carry. An engine's own state keys on the `am=` marker in the TXT record, which the engine writes itself. A device's state keys on the MAC prefix derived from its UDN, which is only correct when upstream had to synthesise the MAC — on Linux that is every interface other than a literal `eth0`, because crosstools' `SendARP()` hardcodes `arp_dev` to `"eth0"`. Where the prefix is not derivable the device state stays unknown rather than being guessed.

A state that was not measured renders as unknown. `false` is allowed only when a scan really ran, completed, and found nothing — a failure, a timeout, an unparsable packet, an expired observation or an unreadable file all produce unknown. The observation expires after five minutes, because it describes a running process, and a stopped engine must not keep showing a positive. Polling never produces it: `status` only reads the cached file, the observation comes from the existing scan action, and no resident process is added.

Field validation lives in one place: `airconnect-manager/rules.js` is loaded by the view and holds the same limits `config.uc` enforces, so the browser rejects what the router would reject, with one message instead of two. `tests/parity/cases.json` is the shared contract and both sides are tested against it. Two speakers resolving to the same effective AirPlay name (an override, else the discovered original name, compared after trailing whitespace) raise a warning row in the Speakers panel on save and on status refresh. It is advisory: the save proceeds, because the engines accept the configuration.

CSS is scoped to `.ac-manager`; neutral background/surface/text/border and positive/warning/focus semantic tokens have light/dark values. Typography inherits the host's system font, preserving LuCI. The page uses 28/19/16px heading sizes, 13px labels and 11–12px supplementary facts. A single column and stacked labels below 600px keep controls reachable on a phone. Native labels, validation, focus rings, semantic disclosure controls, keyboard tabs and textual status states support keyboard and assistive technology use. The interface does not animate.

State refresh updates facts and badges only, never form values. Polling is ten seconds, skips hidden documents, serializes requests and backs off to sixty seconds on repeated failure. Logs and full discovery run only on explicit actions. Configured devices remain visible when absent from discovery. Save parses every native form, sends the canonical proposed UCI payload to backend validation, and only stages valid settings. Save & Apply delegates UCI confirmation/rollback and service reload to LuCI. The manager does not infer application success from an RPC return or launch a second restart.

`dev/` executes the production view with an explicitly labelled mock backend and synthetic devices for visual/interaction inspection. The view and its shared validation rules exist and run against that mock; the rules are host-tested. Loading the same view inside real LuCI with real rpcd/UCI apply and rollback, and real audio verification, remain separate gates that have not been passed.
